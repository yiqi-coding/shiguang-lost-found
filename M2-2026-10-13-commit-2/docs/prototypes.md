# 「拾光」前端原型与交互说明（Baseline v1.0）

> 状态：**已冻结**（M0 里程碑交付物 D1）
>
> 交付形态：**低保真线框原型（ASCII） + 高保真实现说明**。Baseline 阶段不产出 Figma 源文件，采用「线框 + 组件映射 + 状态清单」三件套，直接指导 `frontend/` 实现。
>
> 设计基调：**干净、可信、学术感**。主色调用深蓝绿（`#1F6F8B`）表达「可信」，强调色用暖橙（`#E8833A`）表示「待处理/风险」，避免使用让用户误以为「已确权」的绿色大按钮。
>
> 术语要求：全站统一使用「候选匹配」「建议归属」「可信度」等**非确定性表述**，禁止出现「确认失主」「自动归还」等措辞。

**关键交互**

- 筛选条件变化 → 重置到第 1 页并重新请求；筛选项同步写入 URL query，**刷新后筛选条件不丢失**（便于演示中直接给评委链接）；
- 「查看候选匹配」按钮仅在 `status ∈ {matched, claiming, pending_review}` 或已有匹配记录时出现；
- 无图记录显示统一的类别占位图，不留空白；
- 手机宽度：卡片改为上下布局，筛选器折叠进「筛选」抽屉。

**状态清单**

| 状态 | 表现 |
|---|---|
| 加载中 | 列表骨架屏 ×5 |
| 空结果 | 「没有找到符合条件的记录，试试放宽筛选条件」+ 重置按钮 |
| 分页越界 | 提示并自动回退到最后一页 |
| 请求失败 | `el-alert` 错误条 + 重试按钮 |

**红线**：列表接口返回中**不含** `hidden_features`；前端也不得缓存或推测该字段。

**验收对照**：F07（隐藏特征不可见）。

**关键交互时序**

```text
用户填写表单
   → 点击「提交发布」（按钮进入 loading，禁用重复提交）
   → POST /api/v1/items (multipart)
   → 成功：
        ├─ ai_status = pending → 显示「AI 正在分析…」进度条 → 轮询/等待回填
        │      ├─ success → 弹出「AI 提取结果确认」抽屉，字段可编辑，保存后
        │      │            attributes_edited_by_user = 1
        │      └─ failed  → 顶部警告条：「AI 分析失败，请手动补充物品属性」，
        │                   ★ 物品已成功发布，不阻断
        └─ ai_status = failed → 直接跳转详情页并提示补充属性
   → 跳转 /items/:id 并 toast「发布成功，正在为你查找候选匹配」
```

**校验规则（前端即时校验 + 后端为准）**

| 字段 | 规则 | 提示文案 |
|---|---|---|
| 标题 | 去空格后 5~80 字 | 「标题需 5~80 字」 |
| 描述 | 10~2000 字 | 「请多描述一些细节（至少 10 字）」 |
| 图片 | JPG/PNG/WEBP，≤10MB，≤3 张 | 「仅支持 JPG/PNG/WEBP，单张不超过 10MB」 |
| 时间 | 不晚于当前 +5 分钟 | 「时间不能晚于当前时间」 |
| 隐藏特征 | 至少 1 条，总长 ≤2000 字 | 「请至少填写 1 条隐藏特征」 |
| 免责声明 | 必须勾选 | 「请先阅读并同意免责声明」 |


**关键交互**

- 左侧待办列表支持按「风险等级」「状态」「时间」排序，**高风险默认置顶**；
- 点击操作按钮 → 二次确认弹窗（含操作摘要与备注必填校验）→ 提交 → 列表状态实时更新 + toast；
- `reject` 与 `request_more_info` 的备注**必填**（10~500 字）；
- 审核完成后，右侧详情区自动切换到下一条待办（可配置），提升批量效率；
- 管理员查看隐藏特征属于**授权行为**，页面标注「本次查看已记录到审计日志」；
- 页面顶部横幅常驻：「可信度仅为辅助依据，请结合实际情况判断」。

**验收对照**：F10（三种动作均可用）、F11（状态流转）、F12（操作有日志）、需求 4.6。

## 11. 跨页面通用组件

| 组件 | 职责 | 关键约束 |
|---|---|---|
| `AppHeader.vue` | 全局导航、身份切换、待办徽标 | 管理台入口仅 admin 渲染；未登录显示「登录」 |

| `DisclaimerBar.vue` | 免责声明条 | 首页全量、其他页精简版 |

## 12. 全局免责声明文案（各处必须一致）

> 本系统提供候选匹配和辅助审核建议，不构成物品所有权的自动认定。最终认领结果由平台管理员根据匹配依据、验证结果和实际交接情况确认。

**禁用词清单**（代码评审时检索拦截）：
`确认失主`、`自动归还`、`已确权`、`保证找到`、`100%匹配`、`AI 认定`

## 13. 响应式与可用性要求

| 断点 | 布局策略 |
|---|---|
| ≥1200px | 双栏/三栏，完整信息密度 |
| 768~1199px | 侧栏收起为顶部标签，列表卡片变宽 |
| <768px | 单栏；筛选进入抽屉；底部固定「＋ 发布」；表格改为卡片列表；分数条纵向排列 |

**可用性底线**（需求 8.2）

- 所有异步操作有 loading 状态，超过 3 秒显示「仍在处理中…」；
- 图片上传显示预览与错误原因；
- AI 分析失败可继续发布且有明确引导；
- 表单校验错误定位到具体字段；
- 关键操作（审核、提交认领）有二次确认；
- 页面刷新后筛选条件与分页通过 URL 保持。
