# “拾光”校园多模态失物检索与可信认领平台

## 外包技术需求说明书（Baseline v1.0）

> 文档用途：供外部开发团队进行需求评估、报价、排期、开发、联调、验收与云端部署。
>
> 项目类型：华为云 AI 创新应用竞赛参赛作品
>
> 目标：完成一个可在华为云在线演示、具备图文跨模态匹配和可信认领闭环的可运行系统。
>
> 重要原则：先完成可运行 MVP，再逐步增强算法；不得以“接入大模型”替代完整业务流程。

---

## 1. 项目概述

### 1.1 项目名称

**拾光——基于多模态检索与隐私验证的校园失物认领平台**

### 1.2 一句话定位

通过图片、文字、时间、地点和物品属性进行失物/拾物候选匹配，并通过隐藏特征问答、风险评估和管理员审核降低冒领风险。

### 1.3 项目背景

传统失物招领平台通常只是信息发布板，用户需要自行浏览大量帖子，无法有效处理以下问题：

- 失主和拾到者对同一物品的描述方式不同；
- 同类物品外观相似，关键词搜索难以区分；
- 图片、文字、时间、地点信息没有统一融合；
- 认领人可能只凭公开信息冒领；
- 信息发布后缺少匹配、审核、交接和归档闭环。

本项目通过 AI 和云服务，将失物招领流程升级为：

```text
发布失物/拾物
    → AI提取物品属性
    → 多模态候选召回
    → 图文、时间、地点综合排序
    → 可解释匹配
    → 隐藏特征验证
    → 管理员审核
    → 认领完成与记录归档
```

### 1.4 目标用户

| 用户 | 主要需求 |
|---|---|
| 失主 | 发布丢失信息、查看候选拾物、发起认领 |
| 拾到者 | 发布拾到信息、寻找可能失主、处理认领申请 |
| 管理员 | 审核认领、管理物品状态、处理争议和异常 |
| 评委/演示用户 | 通过浏览器查看完整业务流程和 AI 效果 |

### 1.5 产品边界

#### 本期必须支持

- 校园场景；
- 失物和拾物两类信息发布；
- 图片上传；
- 文字和结构化属性提取；
- 图文、时间、地点综合匹配；
- 匹配结果解释；
- 隐藏特征验证；
- 管理员审核；
- RDS、Redis、OBS、MaaS 等华为云能力接入；
- 云端部署和在线 Demo。

#### 本期明确不做

- 人脸识别；
- 自动判定某人绝对为真实失主；
- 微信支付、物流寄送；
- 全校真实统一身份认证；
- 实时视频追踪；
- 自研基础大模型；
- 复杂移动端 App；
- 区块链存证；
- 面向所有城市或所有行业的泛化系统。

## 2. 外包交付目标

外包团队需交付一个能够完成以下完整演示的系统：

1. 用户发布一条“黑色无线耳机丢失”记录，上传图片并填写时间、地点、公开特征和隐藏特征；
2. 用户发布一条“在图书馆捡到黑色耳机”记录，上传另一角度图片；
3. 系统提取两条记录的物品属性；
4. 系统召回并排序候选匹配记录；
5. 页面展示综合匹配分、各维度分数和匹配依据；
6. 认领者发起认领；
7. 系统生成隐藏特征验证问题，但不泄露标准答案；
8. 认领者提交答案；
9. 系统进行规则/语义验证并生成可信度结果；
10. 管理员查看匹配依据和验证结果；
11. 管理员通过审核；
12. 物品状态更新为“已认领”，并保留操作日志；
13. 系统部署在华为云，评委可通过浏览器访问。

**验收时不得通过直接修改数据库来模拟关键流程。**

## 3. 建议技术方案

### 3.1 总体架构

```text
浏览器
  ↓ HTTPS
前端 Web 应用（Vue 3）
  ↓ REST/JSON
后端 API（FastAPI）
  ├── 用户与权限模块
  ├── 物品发布模块
  ├── 文件上传模块
  ├── 匹配编排模块
  ├── 可信认领模块
  ├── 管理审核模块
  └── 云服务客户端
       ├── 华为云 OBS：图片/附件
       ├── 华为云 RDS MySQL：业务数据
       ├── 华为云 Redis：缓存/会话
       ├── 华为云 MaaS：文本/图片理解与生成
       └── 向量检索：图文向量召回

算法服务（可与后端同项目或独立服务）
  ├── 文本属性提取
  ├── 图像/文本向量化
  ├── 跨模态相似度
  ├── 多源信息融合评分
  └── 认领可信度评估
```

### 3.2 推荐技术栈

| 层级 | 推荐技术 | 要求 |
|---|---|---|
| 前端 | Vue 3 + Vite + TypeScript + Element Plus | 响应式 Web 页面，适合 Demo |
| 后端 | Python 3.11 + FastAPI + Pydantic | REST API，自动生成 OpenAPI 文档 |
| ORM | SQLAlchemy 2.x + Alembic | 支持本地 MySQL 与华为云 RDS 切换 |
| 数据库 | MySQL（本地）/华为云 RDS MySQL | 业务数据持久化 |
| 缓存 | Redis | AI 结果、匹配结果、短期会话 |
| 文件 | 本地开发目录/华为云 OBS | 图片和附件存储 |
| 算法 | Python，向量模型/多模态模型可插拔 | 不得把模型调用写死在业务路由中 |
| 部署 | Docker + Docker Compose，或华为云容器/云服务器 | 必须提供部署文件 |
| 接口测试 | pytest + httpx + Postman/Apifox | 提供自动化测试和接口集合 |
| 版本管理 | Git，Gitee 或 GitHub | 提供完整提交历史或至少可追溯版本 |

## 4. 功能需求

## 4.1 用户与权限

### 4.1.1 用户角色

#### 普通用户

- 发布失物或拾物；
- 查看公开物品列表和详情；
- 查看与自己相关的匹配结果；
- 发起认领；
- 回答验证问题；
- 查看自己的发布、认领记录。

#### 管理员

- 查看全部物品；
- 查看全部匹配和认领申请；
- 查看隐藏特征；
- 审核认领；
- 修改异常记录状态；
- 查看操作日志；
- 管理物品分类和系统配置。

### 4.1.2 权限硬性要求

1. 普通用户不能读取其他物品的 `hidden_features`；
2. 普通用户不能直接将物品状态修改为 `claimed`；
3. 认领者不能查看标准验证答案；
4. 管理员操作必须写入 `audit_logs`；
5. 前端隐藏字段不属于安全措施，必须由后端 API 实施权限控制。

---

## 4.2 物品发布

### 4.2.1 发布类型

- `lost`：我丢失了物品；
- `found`：我拾到了物品。

### 4.2.2 支持类别

Baseline 先支持：

- 无线耳机；
- 水杯；
- 书籍；
- 校园卡/证件；
- 雨伞；
- 背包/文具袋；
- 其他。

### 4.2.3 发布字段

| 字段 | 必填 | 说明 |
|---|---:|---|
| `post_type` | 是 | `lost` 或 `found` |
| `category` | 是 | 物品类别 |
| `title` | 是 | 标题，长度 5～80 字 |
| `description` | 是 | 描述，长度 10～2000 字 |
| `image` | 否 | jpg/jpeg/png/webp，单张不超过 10 MB |
| `color` | 否 | 颜色 |
| `brand` | 否 | 品牌/型号 |
| `location` | 是 | 校园地点 |
| `event_time` | 是 | 丢失/拾取时间 |
| `public_features` | 否 | 对外展示特征 |
| `hidden_features` | 是 | 仅发布者和管理员可见 |
| `contact_id` | 否 | 脱敏联系方式 |

### 4.2.4 图片要求

- 允许格式：JPEG、PNG、WEBP；
- 单张不超过 10 MB；
- 第一版每条记录最多 3 张图片；
- 上传后进行 MIME、大小、扩展名和图片可解析性校验；
- 原始文件名不得直接作为对象存储 Key；
- 建议对象 Key：`items/{yyyy}/{mm}/{uuid}.{ext}`；
- 不允许上传 HTML、SVG 脚本或可执行文件；
- 图片 URL 应使用签名 URL 或受控访问策略，不能无条件公开私有桶。

## 4.3 AI 属性提取

用户提交图片和文字后，系统应提取统一的结构化属性。建议格式：

```json
{
  "category": "无线耳机",
  "brand": null,
  "model": null,
  "color": "黑色",
  "material": null,
  "visible_features": [
    "椭圆形充电盒",
    "盒体右侧疑似有划痕"
  ],
  "accessories": [
    "左右耳机",
    "充电盒"
  ],
  "keywords": [
    "蓝牙耳机",
    "黑色",
    "无线"
  ],
  "uncertainties": [
    "品牌标识不清晰"
  ]
}
```

要求：

1. AI 输出必须经过 JSON Schema 校验；
2. AI 失败时不得导致发布失败，可保存原始描述并标记 `ai_status=failed`；
3. 用户可修改 AI 结果；
4. 用户修改后的属性优先级高于 AI 自动属性；
5. 记录模型名称、提示词版本和分析时间，便于复现和答辩说明；
6. 不得把 AI 结果直接表述为确定事实，应保留不确定性。

## 4.4 多模态候选匹配

### 4.4.1 匹配流程

```text
接收查询物品
  → 结构化字段过滤
  → 文本/图文向量候选召回
  → 时间和地点过滤/加权
  → 多源信息综合评分
  → 生成 Top-K 候选
  → 生成可解释结果
```

### 4.4.2 推荐评分模型

Baseline 使用可解释加权模型：

```text
总分 =
  0.20 × 类别分
+ 0.25 × 属性/文本分
+ 0.20 × 图像相似度
+ 0.15 × 时间合理度
+ 0.15 × 地点合理度
+ 0.05 × 品牌/型号分
```

所有分数归一化到 `[0, 1]`，总分也归一化到 `[0, 1]`。

评分模型必须配置化，例如：

```yaml
matching_weights:
  category: 0.20
  attribute: 0.25
  image: 0.20
  time: 0.15
  location: 0.15
  brand_model: 0.05
```

不得把权重散落在多个文件中。

### 4.4.3 时间分

要求：

- 时间越接近，分数越高；
- 对失物时间范围和拾取单点时间均要兼容；
- 时间相差过大时显著降分；
- 时间缺失不能导致程序崩溃，应标记为未知并采用可配置的中性分。

### 4.4.4 地点分

Baseline 可采用校园地点层级映射：

```text
同一具体地点：1.00
同一建筑不同楼层：0.85
相邻建筑：0.60
同一校区较远地点：0.35
不同校区：0.10
未知：0.50
```

地点规则必须写入配置或数据库，不能只写死在前端。

### 4.4.5 输出解释

每个候选结果必须返回：

- 总匹配分；
- 各维度分数；
- 正向匹配依据；
- 不确定因素；
- 风险提示。

示例：

```json
{
  "total_score": 0.88,
  "score_detail": {
    "category_score": 1.0,
    "attribute_score": 0.92,
    "image_score": 0.81,
    "time_score": 0.95,
    "location_score": 1.0,
    "brand_model_score": 0.5
  },
  "evidence": [
    "物品类别一致",
    "颜色一致",
    "时间相差约1小时20分钟",
    "地点位于同一栋图书馆"
  ],
  "uncertainties": [
    "品牌信息未确认",
    "两张图片拍摄角度不同"
  ]
}
```

### 4.4.6 Top-K

- 默认返回 Top 5；
- 总分低于可配置阈值的记录不展示为“高匹配”；
- 页面必须明确“候选匹配不等于确认归属”；
- 匹配结果需要缓存，但物品信息更新后必须使缓存失效。

## 4.5 可信认领与防冒领

### 4.5.1 特征分级与验证方向

发布时将物品特征分为：

#### 公开特征

- 类别；
- 大致颜色；
- 大致地点；
- 大致时间；
- 普通外观描述。

#### 隐藏特征

- 特殊划痕；
- 个性贴纸；
- 蓝牙设备名称；
- 物品内部内容；
- 特殊磨损；
- 配件缺失情况。

### 4.5.2 验证问题

认领时系统生成 2～3 个问题。问题可以由 MaaS 生成，但必须经过程序校验并且不得泄露答案。

示例：

```text
请描述充电盒上的特殊痕迹。
请填写你设置的蓝牙设备名称。
请说明耳机盒内是否缺少某个配件。
```

### 4.5.3 可信度评分

建议：

```text
可信度分 =
  0.60 × 隐藏特征答案匹配
+ 0.20 × 候选物品综合匹配分
+ 0.10 × 发布信息完整度
+ 0.10 × 行为/风险规则分
```

可信度只是辅助审核依据，不得作为自动确权结论。

### 4.5.4 答案处理

- 标准答案不得返回前端；
- 标准答案不得写入普通日志；
- 建议保存答案摘要或加盐哈希，不保存不必要的明文；
- 语义匹配应容忍合理同义表达；
- 关键字段如设备名称可采用精确/规范化匹配；
- 验证失败后可以允许重新提交，但必须限制次数；
- 连续失败应增加风险标记并通知管理员。

### 4.5.5 认领状态流转

```text
published
  → matched
  → claiming
  → pending_review
  → claimed / rejected / request_more_info
```

状态变更必须由后端控制，并写入操作日志。

---

## 4.6 管理员审核

管理员审核页面至少展示：

- 失物和拾物公开信息；
- 匹配总分和维度分数；
- 匹配依据和不确定因素；
- 隐藏特征验证是否通过；
- 可信度评分；
- 双方账号和脱敏联系方式；
- 历史操作日志；
- 当前物品状态。

管理员操作：

- 通过认领；
- 驳回认领；
- 要求补充信息；
- 暂停物品；
- 标记为争议；
- 关闭记录。

所有操作均需保存：操作人、时间、动作、目标对象、备注和请求追踪 ID。

## 6. REST API 规范

### 6.1 通用要求

- 前缀：`/api/v1`；
- 数据格式：JSON；
- 上传接口：`multipart/form-data`；
- 时间统一使用 ISO 8601；
- 后端返回 HTTP 状态码和业务错误码；
- 自动生成 Swagger/OpenAPI 文档；
- 每个请求生成 `X-Request-ID`；
- 所有分页接口使用 `page`、`page_size`；
- 默认 `page_size <= 50`。

### 6.2 统一成功响应

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "request_id": "req_xxx"
}
```

### 6.3 统一错误响应

```json
{
  "code": "ITEM_NOT_FOUND",
  "message": "物品记录不存在",
  "detail": null,
  "request_id": "req_xxx"
}
```

错误码至少支持：

```text
VALIDATION_ERROR
UNAUTHORIZED
FORBIDDEN
ITEM_NOT_FOUND
CLAIM_NOT_FOUND
MATCH_NOT_FOUND
ALGORITHM_SERVICE_ERROR
STORAGE_SERVICE_ERROR
AI_SERVICE_ERROR
RATE_LIMITED
INTERNAL_ERROR
```

### 6.4 接口清单

#### 健康检查

```http
GET /health
```

返回数据库、Redis、OBS 配置状态，但不得返回密钥。

#### 发布物品

```http
POST /api/v1/items
Content-Type: multipart/form-data
```

字段：`post_type`、`category`、`title`、`description`、`color`、`brand`、`location`、`event_time`、`public_features`、`hidden_features`、`image`。

返回物品 ID、状态、图片 Key 和 AI 分析状态。

#### 物品列表

```http
GET /api/v1/items?post_type=found&category=无线耳机&status=published&page=1&page_size=20
```

普通用户不得在返回中看到 `hidden_features`。

#### 物品详情

```http
GET /api/v1/items/{item_id}
```

按角色和物品关系进行字段脱敏。

#### 获取匹配结果

```http
GET /api/v1/items/{item_id}/matches
```

支持 `top_k`，默认 5；返回总分、维度分、依据和不确定因素。

#### 重新计算匹配

```http
POST /api/v1/items/{item_id}/match
```

需要鉴权；结果写入数据库并缓存。

#### 发起认领

```http
POST /api/v1/claims
```

请求：

```json
{
  "match_id": 3001
}
```

返回认领 ID 和验证问题，不返回答案。

#### 提交认领验证

```http
POST /api/v1/claims/{claim_id}/verify
```

请求：

```json
{
  "answers": [
    {"question_id": "q1", "answer": "盒子右侧有划痕"},
    {"question_id": "q2", "answer": "YiQi-AirPods"}
  ]
}
```

返回验证分、风险等级和审核状态。

#### 我的发布记录

```http
GET /api/v1/me/items
```

#### 我的认领记录

```http
GET /api/v1/me/claims
```

#### 管理员认领审核

```http
POST /api/v1/admin/claims/{claim_id}/review
```

请求：

```json
{
  "action": "approve",
  "comment": "匹配依据和隐藏特征验证均通过"
}
```

`action` 取值：`approve`、`reject`、`request_more_info`。

#### 管理员查看日志

```http
GET /api/v1/admin/audit-logs?target_type=claim&target_id=4001
```

### 7.1 匹配接口

返回：

## 10. 安全与隐私要求

1. 所有密钥、Token、数据库密码通过环境变量注入；
2. `.env` 不得提交到 Git；
3. 提供 `.env.example`，只包含变量名和示例占位符；
4. 真实数据不得上传到公共仓库；
5. 证件、联系方式、蓝牙名称等敏感内容必须脱敏；
6. 普通用户不能读取隐藏特征；
7. 日志不得记录完整隐藏答案、Secret、Authorization Header；
8. 上传文件必须校验类型、大小和内容；
9. 接口要有基本限流，尤其是登录、认领和 AI 调用接口；
10. 管理员接口必须鉴权；
11. AI 结果仅作辅助，不得宣称“自动确认所有权”；
12. 页面显示隐私提示和免责声明；
13. 数据库备份和云资源权限遵循最小权限原则；
14. 生产环境使用 HTTPS 或由云端网关终止 HTTPS。

免责声明建议：

> 本系统提供候选匹配和辅助审核建议，不构成物品所有权的自动认定。最终认领结果由平台管理员根据匹配依据、验证结果和实际交接情况确认。

| F14 | 重启恢复 | 重启后业务数据不丢失 |

### 13.2 接口验收

- 所有接口有 OpenAPI 文档；
- 参数错误返回 4xx，不返回 500；
- 不存在对象返回规范错误；
- 无权限访问返回 401/403；
- 每个接口有至少一个成功测试和一个异常测试；
- 后端自动化测试通过率 100%；

- 普通用户无法通过接口读取隐藏字段；
- 普通用户无法越权审核认领；
- `.env` 未进入 Git；

- 上传非法文件被拒绝；

- 普通列表/详情接口 P95 < 1 秒；

- 未缓存 AI 分析应有明确加载状态和超时机制；
- 单次图片上传不超过 10 MB；
- AI/算法服务超时默认 30 秒，超时后返回可理解错误并允许重试；
- 并发 20 个演示用户时核心接口不崩溃。

### 13.5 失败降级

以下服务失败时不得造成整个系统不可用：

| 失败服务 | 降级策略 |
|---|---|
| MaaS | 保存原始文本，AI 状态标记 failed，允许手动填写属性 |
| 算法服务 | 使用 Mock/规则匹配并明确标记为降级结果 |
| Redis | 直接访问数据库，不影响核心业务 |
| OBS | 阻止无图片发布或允许无图发布，返回清晰错误 |
| RDS | 核心业务不可用，但页面展示维护提示 |

## 18. 项目风险与处理方案

| 风险 | 影响 | 处理方案 |
|---|---|---|
| MaaS 额度/接口未及时开通 | AI 无法调用 | 先实现 Mock 和可替换客户端 |
| 图像模型效果不稳定 | 匹配指标低 | 图像分与结构化字段融合，不单依赖图像 |
| 数据集质量不足 | 指标不可信 | 提前制作正负样本和 hard negative |
| 云资源网络不通 | 无法部署 | 先做本地 Docker，再按区域和安全组排查 |
| 隐私字段泄露 | 安全风险 | 后端字段级权限和接口测试 |
| 前后端字段不一致 | 联调延期 | 冻结 API 契约，变更必须记录版本 |
| 算法开发延期 | 主流程被卡住 | 先用 Mock，真实算法独立替换 |
| 过度依赖大模型 | 结果不可复现 | 数值、状态和权限由程序控制 |
| 外包团队无法交接 | 后续无法维护 | 要求源代码、部署脚本、文档和云资源清单 |
